# Studies

The catalog at [choxos.github.io/ITC-open-problems](https://choxos.github.io/ITC-open-problems/)
records 336 open methodological problems in indirect treatment comparisons. This
directory is the attempt to close some of them.

One study a week, each aimed at a single catalog entry, taken in priority order
from the queue. Scope is population-adjusted indirect comparison only: MAIC, STC,
ML-NMR, ML-UMR and NMI. Plain network meta-analysis is out of scope because it
does not adjust for population differences, which is where these problems live.

Each study produces a manuscript in Markdown, PDF and OpenDocument, and a section
on the problem's own page in the catalog stating what was found and what was not.

## What gets studied

Not every open problem can be settled by a study, and the difference is not
cosmetic. A simulation can measure bias, coverage and error rates; it can show
how badly a known nonidentification bites at realistic sample sizes; it can give
a diagnostic its operating characteristics. It cannot establish that a package is
missing, that clinicians misread a plot, that a field under-reports something, or
that a quantity is unidentifiable in principle. Those need software, a case
study, a meta-research corpus, or a proof.

Every catalog entry was triaged on both questions separately, by an external
model, before the program started: is this a population-adjustment problem, and
what kind of study would settle it. The queue is the intersection. The full
triage, including the reasons entries were excluded, is regenerated by
`build/studies/triage.py`.

## How a study runs

1. **Design.** The problem statement, its prior work and its proposed direction
   go to an external model at maximum reasoning effort, which returns a design.
   The design is then challenged: what would make this study answer a question
   nobody asked, and what result would be an artifact of the data-generating
   mechanism rather than a property of the methods?

2. **Protocol.** `protocol.md` is written and committed **before any result is
   seen**. It fixes the aims, the data-generating mechanisms, the estimands, the
   methods compared, the performance measures and the replicate count, and it
   states in advance what result would count as answering the problem and what
   would count as failing to. The commit that adds it is the timestamp.

3. **Run.** R, seeded, resumable, parallel. Replicate failures are recorded and
   reported, never dropped.

4. **Analyze.** Performance measures with Monte Carlo standard errors on every
   one.

5. **Write.** The manuscript sets out the problem mathematically, reviews what is
   known, gives the design, reports the results, and states plainly what the
   study does not answer.

6. **Publish.** Rendered to three formats and linked from the catalog page.

## Reporting standard

Simulation studies follow ADEMP: aims, data-generating mechanisms, estimands,
methods, performance measures. Morris, White and Crowther (2019),
[doi:10.1002/sim.8086](https://doi.org/10.1002/sim.8086).

Two rules that follow from it and are enforced rather than encouraged.

**Every performance measure carries a Monte Carlo standard error.** A bias of
0.02 is uninterpretable without knowing whether the MCSE is 0.001 or 0.03. The
replicate count is justified in the protocol from a target MCSE, not chosen
because it is a round number.

**Failed replicates are results.** A method that converges on 60% of replicates
and is unbiased on those is not an unbiased method. Convergence rates are
reported for every method in every scenario.

## Layout

```
studies/
  _shared/R/performance.R    ADEMP performance measures with MCSEs
  _shared/R/harness.R        seeded, resumable, parallel replicate runner
  index.json                 generated; what the site reads
  <PROBLEM-ID>-<slug>/
    study.json               metadata: question, answer, limits, links
    protocol.md              committed before the run
    R/                       the study, numbered in execution order
    results/summary.csv      tracked
    results/raw/             gitignored; regenerable from the seed
    results/provenance.md    R and package versions that produced the results
    manuscript/manuscript.qmd
    out/<PROBLEM-ID>.{md,pdf,odt}
```

Studies live in directories on `main`, not on branches. The catalog page links to
the code, and a link into a branch is dead in the deployed site; the site is
built from `main`, so a study on a branch could not ship its manuscript and its
registry entry in one commit; and the shared harness could not be reused without
duplicating it into every branch.

## Reproducing a study

```bash
cd studies/<PROBLEM-ID>-<slug>
Rscript R/03-run.R          # writes results/raw/, resumable
Rscript R/04-analyze.R      # writes results/summary.csv
Rscript R/05-figures.R
python3 ../../build/studies/publish.py --study <PROBLEM-ID>
```

Replicate seeds derive from one master seed through L'Ecuyer-CMRG streams, so a
run gives identical results on any number of cores and an interrupted run resumes
rather than restarting. `results/provenance.md` records the R and package
versions that produced the committed numbers; `multinma` 0.9.1 and 0.9.1.9002 are
different estimators, and a result that moves between them is a finding.

## Standing on

Where a study compares against an established benchmark it uses the published
one rather than inventing a new mechanism, so results are comparable:

- Phillippo, Dias, Ades and Welton (2020), *Assessing the performance of
  population adjustment methods for anchored indirect comparisons*,
  [doi:10.1002/sim.8759](https://doi.org/10.1002/sim.8759)
- Remiro-Azócar, Heath and Baio (2021), *Methods for population adjustment with
  limited access to individual patient data*,
  [doi:10.1002/jrsm.1511](https://doi.org/10.1002/jrsm.1511)
