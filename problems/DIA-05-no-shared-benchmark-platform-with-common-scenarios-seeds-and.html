No shared benchmark platform with common scenarios, seeds and truth

Statement

No shared platform runs the field’s methods on common data-generating mechanisms with published scenarios, seeds, code and ground truth, so nothing accumulates across papers and the ranking of methods under assumption failure cannot be read off the literature. The oracle claim does not survive scrutiny: Phillippo et al. 2020 (doi:10.1002/sim.8759) defines truth as what a gold-standard correctly specified IPD network meta-regression would estimate, and the general-likelihood ML-NMR work (arxiv:2401.12640) includes full-IPD reference comparisons. A single full-IPD oracle also cannot separate information loss from method failure, because it changes data granularity, covariate availability and model specification at the same time; that decomposition needs nested arms that vary one feature at a time. The proposed 28-family minimum comparator set is a design proposal rather than a derived requirement, and several of its categories overlap.

Why it is open

Data-generating mechanisms, estimands and performance measures differ between papers, so published rankings do not compose and each new comparison starts over. Average-case simulation under correct specification rewards efficiency in a regime applied HTA data are rarely in, and building adversarial mechanisms that break one’s own method runs against the incentives of a methods paper. A shared benchmark needs shared code, shared scenarios and a maintainer, which is infrastructure work with no conventional publication reward.

Probable solution or research direction

Build a public benchmark that prespecifies estimands, combines benign and adversarial scenarios, verifies implementations against known analytic results, and publishes scenarios, seeds, code and ground truth so that results accumulate. Choose the comparator set by applicability to each scenario rather than by a fixed family count, and where information loss is the question use nested paired arms that change one feature at a time (data granularity, covariate availability, model specification) instead of a single full-IPD oracle. Score on bias, coverage, ESS collapse, decision error and runtime, and report excess error against the appropriate nested reference rather than raw bias alone.

Verification

Verdict. Confirmed open. Auditors agreed the problem is open and no counterevidence surfaced.

The source titled this. “No neutral adversarial benchmark, comparator set, or oracle arm” The title says no oracle arm exists, but the audit found a gold-standard full-IPD reference already defined and used, and rejected the 28-family comparator set as a derived requirement.

The source said. “No shared simulation platform compares the field’s methods on common data-generating mechanisms; published comparisons are pairwise contests run by method authors under benign conditions, against a handful of chosen comparators, and almost never include an oracle analysis that uses full IPD, the true bias variables and correct models. Consequently neither the ranking of methods under assumption failure nor the separation of information loss from method failure can be read off the literature.”

What was wrong with it. The source said PAIC simulations almost never include an oracle and that a minimum comparator set contains 28 method families; the literature auditor found the gold-standard full-IPD reference already explicit in Phillippo et al. 2020 (doi:10.1002/sim.8759) and full-IPD comparisons in arxiv:2401.12640, and GPT-5.6 Sol found no argument establishing 28 as a minimum, noting that exponential-tilting MAIC and entropy balancing can be dual formulations of the same calibration problem and that trimming is a tuning choice. The entry’s two prior_work items carried no locators; the literature auditor identified them as Phillippo et al. 2020 and Hatswell et al. 2020 (doi:10.1016/j.jval.2020.02.008), which are now cited.

Literature and prior-art check
open / supported-with-caveat. Citation fidelity: the two prior_work entries carry no DOI, but they map cleanly onto real papers whose descriptions match. ‘Phillippo and colleagues, anchored population-adjustment simulation’ is Phillippo, Dias, Ades & Welton 2020 (Stat Med 39:4885-4911), which is exactly an anchored population-adjustment simulation of ML-NMR, MAIC and STC. ‘Hatswell and colleagues, unanchored misspecification simulation’ is Hatswell, Freemantle & Baio 2020 (Value Health 23:751-759), ‘The Effects of Model Misspecification in Unanchored Matching-Adjusted Indirect Comparison’. Both are accurately characterized; supplying the locators would make them non-decorative. I found no public neutral adversarial benchmark platform for PAIC; outstandR is a unified software interface, not a benchmark with shared scenarios and published ground truth. The oracle claim is too strong: Phillippo 2020 explicitly defines truth as what a gold-standard correctly specified IPD network meta-regression would estimate, and full-IPD reference arms are actually run in ML-NMR and IPD-NMA simulation work. The ‘28 method families’ figure is a design proposal, not a checkable fact. GPT-5.6 Sol, technical and source-code lens
open / overstated. C6 is correct, C7 is a sound design principle, and C11 correctly counts ten grouped scenario families. The remainder is inflated. No mathematical or decision-theoretic argument establishes 28 families as a minimum, and several categories overlap. Conventional exponential-tilting MAIC and entropy balancing can be dual formulations of the same calibration problem when they use identical moments and base weights; trimming is a tuning intervention rather than necessarily a separate method family. A single full-IPD oracle cannot separate information loss from method failure because it simultaneously changes data granularity, available covariates, and model specification. That decomposition requires nested paired arms that change one feature at a time. Simulation truth itself can be the relevant reference, so an estimated oracle need not appear in every scenario. Claims about the absence of public benchmarks, author behavior, and routine oracle omission are literature claims unsupported here. A shared adversarial benchmark would be useful infrastructure, but not a decision-grade requirement in the asserted form.
