Target-standardized marginal risks are not the HTA reporting default

Outcome-specific problems
Very high priority
Overstated

OUT-01 Overstated Very high priority Established

Statement

Outcome-regression population-adjusted comparisons that report covariate-conditional coefficients, namely plug-in-means STC and conditional ML-NMR effects, return odds ratios that are not the marginal contrast the aggregate-data trial published, because the odds ratio is non-collapsible. This is not a property of binary PAIC as a class: a MAIC that fits a weighted outcome model containing treatment only already returns a marginal effect in the target population. Estimators and software for target-standardized marginal risks, risk differences and risk ratios already exist, including parametric G-computation (pmid:35485582), multiple-imputation marginalization, outstandR, maicplus and multinma’s marginal_effects(). What remains is that these are not the reporting default in HTA submissions, and that marginal component effects are not generally additive, so the scale chosen for standardization has to be compatible with component synthesis.

Why it is open

The gap is between available methods and prevailing practice: conditional coefficients are still reported alongside marginal aggregate-data effects, and nothing in the output signals the mismatch because both are labeled odds ratios of plausible magnitude. Standardizing the conditional side requires both a fitted outcome model and an explicit target covariate distribution, which aggregate publications rarely supply, so the comparator side cannot be moved onto the conditional scale after the fact. Conditional and marginal odds ratios do coincide under the null, with no prognostic heterogeneity, or with a degenerate covariate distribution, so the mismatch is decision-critical when incompatible estimands are actually combined rather than automatically. Within cpaic, the unreleased development package, cML-NMR still has no marginal standardization path.

What has been tried

Work What it contributes
Remiro-Azocar, Heath and Baio 2022, Target estimands for population-adjusted indirect comparisons, Statistics in Medicine establishes that HTA agencies make reimbursement decisions at the population level and therefore require marginal estimands, and diagnoses the conditional versus marginal conflation in PAIC
Parametric G-computation for compatible indirect treatment comparisons with limited individual patient data, 2022 (PMID 35485582) outcome-regression estimator that targets a marginal treatment effect compatible with the aggregate-data trial’s published marginal effect, for binary outcomes
outstandR: Model-Based Standardisation for Indirect Treatment Comparison with Limited Subject-Level Data (CRAN) CRAN implementation of model-based standardization for PAIC, producing marginal contrasts on user-chosen scales
maicplus 0.1.2 (CRAN) the literature auditor quotes its release notes, ‘changed the link function to binomial for RD and RR in binary analysis’, so it produces risk differences and risk ratios rather than only odds ratios
multinma 0.7.0 (2024-05-07), marginal_effects() produces population-average marginal treatment effects on difference, ratio and link scales, standardized to a target population supplied through newdata or baseline, from an ML-NMR fit
cpaic, unreleased development package on GitHub (not on CRAN), commit 9d150e9, README.md and R/cmaic.R documents the estimand distinction, that cstc() returns a conditional effect at the target covariate values while cmaic() returns a marginal weighted effect in the target population and that these differ on non-collapsible scales, and records that marginal component effects are not generally additive; cML-NMR has no marginal standardization path

Probable solution or research direction

The estimators exist, so the work is adoption and extension rather than construction. Make a named target-population estimand and marginal standardization the declared default in submissions, using the existing implementations, and add a marginal standardization path to cML-NMR where one is still missing. Check in each analysis that the effect scale chosen for standardization is compatible with component synthesis, since marginal component effects add exactly when the standardized treatment effects remain affine in the component design.

Verification

Verdict. Overstated. 2 independent auditors judged the claim as stated too strong. Plug-in-means STC and conditional ML-NMR coefficients return covariate-conditional odds ratios that, because the odds ratio is non-collapsible, are not the marginal contrast published by the AgD trial; methods (parametric G-computation, multiple-imputation marginalisation, multinma marginal_effects) and software (outstandR, maicplus, multinma) that produce target-standardised marginal risks, risk differences and risk ratios already exist, but they are not yet the reporting default in HTA submissions.

The source titled this. “Odds-ratio default and conditional-marginal mismatch in binary PAIC” The title attributes the conditional-marginal mismatch to binary PAIC as a class, which both auditors rejected since weighted MAIC already returns a marginal target-population effect.

The source said. “Binary population-adjusted indirect comparisons report conditional odds ratios because logistic models are convenient, but the odds ratio is non-collapsible, so the covariate-adjusted coefficient estimated from individual patient data is neither the marginal contrast in any named population nor on the same scale as the marginal effect published by the aggregate-data trial it is combined with.”

What was wrong with it. The source attributed the conditional-marginal mismatch to binary PAIC as a class and to the convenience of logistic models, and both auditors rejected that scope. The literature auditor found the estimand problem already named in Remiro-Azocar, Heath and Baio (doi:10.1002/sim.9413), solved by parametric G-computation (pmid:35485582), and implemented in outstandR, maicplus and multinma; the code auditor confirmed at commit 9d150e9 of cpaic, an unreleased development package on GitHub that is not installable from CRAN, that cmaic() returns a marginal weighted effect while cstc() and cmlnmr() return conditional ones.

How the evidence falls in time

6 papers in the reviewed corpus bear on this problem, published 2016 to 2025. The most recent paper to touch this reports progress on it, and every paper calling it open is older.

It is also being closed in pieces: partial results come from more than one paper in more than one year, each covering a different part.

Does the later work answer the earlier work? Put to an independent reviewer with the older and newer claims side by side, it judged that the later work does not answer it (high confidence). The later work demonstrates and recommends target standardization, but the earlier gap is specifically about routine reporting practice rather than methodological availability. Neither later claim shows that HTA submissions have adopted marginal risks, risk differences, or risk ratios as the default output. What remains: Target-standardized marginal risks and compatible component-scale reporting are still not established as the HTA submission reporting default.
