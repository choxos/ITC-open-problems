multinma lacks partial IPD, missing data and a data-informed bridge

Software, benchmarks & interface standards
Very high priority
Overstated
Open multinma issues include missing data (#67), mixed aggregate and individual data within one study (#58), mixed likelihoods (#42) and the interpretation and ranking of some time-to-event auxiliary parameters (#52), and data-informed baseline connections for disconnected networks existed only as unmerged pull request #68 at inspection. Baseline-risk adjustment and marginal effects in external target populations are not open needs: the former is a released feature announced in the 0.9.0 release notes through the new .mu regression variable following TSD3, and the latter was confirmed implemented by the maintainer when closing issue #59 on 11 December 2025, documented in the plaque psoriasis vignette with the method published as Phillippo et al. (doi:10.1177/0272989X221117162). Released multinma will also fit a disconnected network; what it lacks is a data-informed bridge, because cross-component relative effects are then determined entirely by priors. The remaining substantive gaps are partial IPD within a study, missing-data modeling inside the integration step, broader mixed-likelihood structures and released support for data-informed disconnected bridges. The mixed-likelihood limitation has a specific and long-standing instance: joining individual time-to-event data to arms reported only as an event count over a stated follow-up requires a survival function in closed form, which excludes the log-normal and log-logistic families, and forces one baseline shape to be shared across data types because an arm summarized by a single events, at-risk and follow-up triple supports one free parameter and cannot identify its own shape. The cost lands on absolute arm-level predictions and on extrapolation beyond the observed follow-up, the quantities health technology assessment depends on, and it is measurable: in the network that introduced the approach the two individual-data trials implied Weibull shapes of 0.93 and 1.27 with non-overlapping credible intervals, so no single shared shape was correct.

NoteScope

This entry describes a limitation of a specific implementation rather than of the field. It is catalogued because the underlying methodological problem is general, and because a reference implementation is where such problems become concrete and checkable.

Statement

Open multinma issues include missing data (#67), mixed aggregate and individual data within one study (#58), mixed likelihoods (#42) and the interpretation and ranking of some time-to-event auxiliary parameters (#52), and data-informed baseline connections for disconnected networks existed only as unmerged pull request #68 at inspection. Baseline-risk adjustment and marginal effects in external target populations are not open needs: the former is a released feature announced in the 0.9.0 release notes through the new .mu regression variable following TSD3, and the latter was confirmed implemented by the maintainer when closing issue #59 on 11 December 2025, documented in the plaque psoriasis vignette with the method published as Phillippo et al. (doi:10.1177/0272989X221117162). Released multinma will also fit a disconnected network; what it lacks is a data-informed bridge, because cross-component relative effects are then determined entirely by priors. The remaining substantive gaps are partial IPD within a study, missing-data modeling inside the integration step, broader mixed-likelihood structures and released support for data-informed disconnected bridges. The mixed-likelihood limitation has a specific and long-standing instance: joining individual time-to-event data to arms reported only as an event count over a stated follow-up requires a survival function in closed form, which excludes the log-normal and log-logistic families, and forces one baseline shape to be shared across data types because an arm summarized by a single events, at-risk and follow-up triple supports one free parameter and cannot identify its own shape. The cost lands on absolute arm-level predictions and on extrapolation beyond the observed follow-up, the quantities health technology assessment depends on, and it is measurable: in the network that introduced the approach the two individual-data trials implied Weibull shapes of 0.93 and 1.27 with non-overlapping credible intervals, so no single shared shape was correct.

Why it is open

The data model still assumes a study is either IPD or aggregate and that studies share a likelihood family, so a partially individual study or a network mixing binary and survival outcomes has no representation in the object. Missing covariate data interacts with the integration step, because the covariate distribution being integrated over is itself partly unobserved, which makes it a modeling problem rather than preprocessing. For disconnected evidence the software already returns an answer, which is the harder problem: nothing in the returned object separates a prior-driven cross-component contrast from a data-informed one, and the baseline-connection work that would supply the data-informed bridge sits in an unmerged branch. The steep learning curve keeps the user base small, which slows the feedback that would settle the remaining interface questions.

multinma disconnected-network development branch for PR #68, dmphillippo/multinma@4786312 partially implements optional baseline connections through con() specifications that share baselines between studies, plus mixed-study handling; not merged into the inspected release
Saramago, Chuang & Soares 2014, BMC Medical Research Methodology 14:105 The only published route joining individual time-to-event data to arms reported as an event count over a stated follow-up: the two data types are linked through a parametric survival function evaluated at each aggregate trial’s follow-up time. Records the price of that link, namely that the choice of survival distribution was limited because families such as the log-logistic and log-normal have no closed-form expression for the probability of the event over time and so cannot support the joint synthesis, and that the baseline shape has to be shared across data types. Reports Weibull shape estimates of 0.93 and 1.27 with non-overlapping credible intervals in the two individual-data trials of the same network, so no single shared shape was correct, and finds absolute arm-level predictions and extrapolation beyond the observed follow-up to be the estimates most sensitive to that specification. Names numerical integration over a flexible baseline inside the aggregate likelihood as the development that is needed.

Probable solution or research direction

Extend the data model to represent partially individual studies, mixed likelihoods across a network and missing covariate or outcome data inside the integration step, and implement missing data as a modeling layer rather than a preprocessing step. Complete and merge the baseline-connection work in PR #68 so disconnected networks can be bridged with data-informed rather than purely prior-driven cross-component effects, and make the prior-driven versus data-driven contribution visible in the returned object so a prior-dominated estimate does not look like any other. Close the outstanding time-to-event interpretation and ranking questions, and drop baseline-risk adjustment and external-target marginal effects from the roadmap because they ship.

Verification

Verdict. Overstated. 2 independent auditors judged the claim as stated too strong. Open multinma issues include missing data (#67), mixed aggregate and individual data within one study (#58), mixed likelihoods (#42) and the interpretation and ranking of some time-to-event auxiliary parameters (#52), and disconnected-network support existed only as unmerged pull request #68 at inspection. Baseline-risk adjustment and marginal effects in external target populations are implemented in the released package (0.9.0/0.9.1), the former announced in NEWS and the latter confirmed by the maintainer when closing issue #59, although issue #35 was left open in the tracker.

The source titled this. “multinma data model omits partial IPD, missing data and disconnection” The title says the data model omits disconnection, but released multinma does fit disconnected networks; what it lacks is a data-informed baseline bridge.

The source said. “Open multinma issues include missing data, mixed aggregate and individual data within one study, mixed likelihoods, baseline-risk adjustment, marginal effects in external populations, and interpretation and ranking of some time-to-event parameters, while disconnected-network support existed only as unmerged pull request #68 at inspection. The most mature open Bayesian NMA/ML-NMR platform therefore had no released support for disconnected evidence at the audit date.”

What was wrong with it. Both auditors found the entry stale in the same two places: baseline-risk adjustment shipped in 0.9.0 (release notes, .mu regression variable, PR #36, with issue #35 left open in the tracker only because it was never closed) and marginal effects in an external target population were already implemented when the maintainer closed issue #59, so listing them as open needs was wrong. GPT-5.6 Sol also found the claim of no released disconnected-network support literally false, since released multinma fits disconnected networks with prior-driven cross-component effects and what PR #68 adds is the data-informed baseline connection; the claim was unattributed in the source and is now sourced.
